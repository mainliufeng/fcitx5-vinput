# voice-input 首轮质量测试与优化（2026-10-02）

已建立并执行 **127 个真实识别案例，25.83 分钟音频**，修复结尾漏解码、纯噪音误提交、
保护边界重复、长语音漏整句和英文拼接。优化后的 daemon 已在本机用户服务中启用。
当前默认仍为 X-ASR 流式预览 + X-ASR 离线精修，未切换模型，未启用 LLM 整理。

**微信输入法、豆包输入法均未实测，不能据此判断达到竞品水平。**
这是内部 before/after。完整协议与操作见 [测试说明](../../../tests/quality/README.md)。

## 测试范围

- 基础真人语音：20 条中文、10 条英文，来自 [Google FLEURS](https://huggingface.co/datasets/google/fleurs)，CC-BY-4.0。
- 60 条固定种子的 20/10 dB 白噪声变体；30 条 10 dB 真实火车背景录音混合变体。
  火车录音由 Daniel Simion 创作，CC-BY-3.0，来源见 [授权页面](https://soundbible.com/2177-Steam-Train-Whistle.html)
  与 [PyTorch 教程](https://docs.pytorch.org/audio/stable/tutorials/audio_data_augmentation_tutorial.html)。
- 4 条拼接长语音，42.4–73.7 秒；另有静音、纯白噪声、纯火车噪声 3 条无目标语音案例。
- 开发集 65 个、保留集 62 个；原始句子按语言和 ID 去重，变体及长语音保持在同一 fold。
  两个 fold 都选自 validation 分区，官方 test 接口当时返回 HTTP 500。
- [40 条录音脚本](../../../tests/quality/recording-prompts.jsonl)已准备，但没有真人录音，不计入已跑成绩。
  因此编程中英混说、数字/否定忠实度、自然纠正、轻声和口音还没有充分覆盖。

加噪、拼接不是更多独立说话人；只有一种真实环境噪声，不能代表办公室、人群或实际耳机录音。
长英文失败样本是在查看保留集后继续修复的，属于已知回归样本，不能称为盲测胜利。

## 默认二级精修结果

中文用 CER，英文用词错误率（评分字段 `mixed_token_error_rate`），越低越好。
下表均来自保留集，短语音中文每组 10 条、英文每组 5 条，长语音每语言 1 条。

| 场景 | 指标 | 原版 | 最终版 |
| --- | --- | ---: | ---: |
| 中文干净语音 | CER | 9.23% | 9.23% |
| 中文 20 dB 白噪声 | CER | 9.49% | 9.49% |
| 中文 10 dB 白噪声 | CER | 10.77% | 10.26% |
| 中文 10 dB 火车背景 | CER | 9.23% | 9.23% |
| 英文干净语音 | 词错误率 | 7.87% | 7.87% |
| 英文 10 dB 白噪声 | 词错误率 | 16.85% | 16.85% |
| 英文 10 dB 火车背景 | 词错误率 | 31.46% | 31.46% |
| 中文长语音 | CER | 1.32% | 1.32% |
| 英文长语音 | 词错误率 | 44.94% | 13.48% |
| 无目标语音（3 条，开发集） | 误提交次数 | 2/3 | 0/3 |

默认模式普通短句大部分没有准确率变化；英文强环境噪声仍明显偏弱。
长英文回归样本 CER 从 40.00% 降至 11.24%。开发集长英文词错误率从 17.24% 降到 16.09%，
但 CER 从 11.70% 升到 12.36%；这是一项局部取舍，不能把所有指标都称为改善。
所有非空参考语音最终都得到非空文字，没有因 VAD 门控整条丢弃。

流式单遍的保留集也有改善：中文干净 CER 10.77% → 9.49%，中文白噪声 10 dB 10.77% → 9.74%；
英文干净词错误率 11.24% → 8.99%，英文白噪声 10 dB 15.73% → 13.48%。
单遍长英文仍较差，词错误率 38.20%，说明尾部修复不能替代离线长语音处理。

## 改动与验证

1. 结束前补齐 1.28 秒静音样本，刷新 X-ASR 960 ms 块的右侧上下文。
   [上游 C API 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/c-api-examples/decode-file-c-api.c)
   使用尾部补齐；本机验证 0.3 秒仍不能补齐该模型部分句尾，因此采用覆盖一个块及边界的长度。
   模型快速处理补齐样本，代码没有等待 1.28 秒。
2. 使用现有 Silero VAD 判定结束时是否有语音，清空无语音的最终结果。
   这修复了原版静音输出 `H`、纯火车噪声输出 `Wah` 的案例；实时预览仍可能暂时出现错误假设。
3. 相邻 VAD 保护区间取有序并集，每个原始采样只消费一次。
   新回归测试在旧实现上失败、修复后通过。
4. 超过 20 秒且含多个 VAD 语音区间的离线片段，按上游 VAD 区间分别解码，减少长注意力上下文漏句。
   任一区间解码为空时保留完整流式回退，避免提交缺段文字。
5. 分片拼接保留英文词边界与句间空格；中文保持原有间隔。词边界/完整回退测试在旧实现上失败。

关闭 VAD 和改用 SenseVoice 两个候选已经测量并拒绝。关闭 VAD 产生无语音误输出，英文干净语音退步；
SenseVoice 在开发集中文噪声和英文上退步。候选逐条结果及评分保留在证据目录。

CMake 构建、4 组 CTest（含 5 项 Python 指标测试）、i18n 校验和变更质量门禁通过。
另用**实际安装的最终二进制**，在独立 D-Bus 与虚拟 PipeWire 源上做实时重放：
正常中文产生最终 `commit_text`，白噪声和火车噪声均为空，状态回到 idle，虚拟设备已卸载。
[实录文字与状态](live-result.json)中正常语音仍有“科隆”→“克隆”等错误，链路通过不代表文字完全准确。
该验收没有向真实编辑器上屏，也没有测试 LLM 整理。

后端结束计算时间在保留集的中位数约为：中文短句 351–359 ms，英文短句 329–360 ms，
这条长英文约 1286 ms。它不包含录音、上屏或网络时间；首轮测试期间有编译/链路验证等并行活动，
精确性能比较须用闲置机器多次重跑，不能把单次耗时差当成确定加速。

## 本机运行与回滚

本机日常 `vinput-daemon.service` 已通过用户级配置运行优化版本：

- 二进制：`~/.local/libexec/vinput/vinput-daemon`
- 配置：`~/.config/systemd/user/vinput-daemon.service.d/quality-build.conf`
- 已核对服务 active/idle、实际进程路径及安装文件与构建文件 SHA256 一致。
- 现有 `llm-env.conf` 与日常语音/热词配置保留。系统包以后更新时，用户级 ExecStart 仍指向本版本；
  要切回系统包，删除上述 `quality-build.conf`，执行 `systemctl --user daemon-reload`
  和 `systemctl --user restart vinput-daemon`（先确认未录音）。

没有在 Git 中提交二进制或真实认证环境。音频在本机 [corpus](../../../tests/quality/corpus/) 内；
[快照清单](manifest.jsonl)、[运行指纹](run-context.json)、逐条识别和分组评分已提交，方便复查。
